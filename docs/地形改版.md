# 地形改版：有山有水、每局都不一样、开局荒芜

这份文档用大白话说明地形改版改了什么、怎么自己验证、老存档会怎样。

## 一句话

以前每关开局是一块**圆形的大平原**，山、湖、树全靠你手工造；现在开局就有**不规则海岸线、起伏坡地和湖**（每局还不一样），而**树和动物留给你自己养**。

## 一、开局是什么样（实测，每局种子随机）

| 关卡 | 陆地格 | 有起伏 | 山（最高） | 水面 | 树 | 小动物 | 能种能放 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 第 1 关 | ~145 | 60%+ | 3（4.0 格） | 3 | 0 | 0 | 92% |
| 第 2 关 | ~220 | 60%+ | 10（4.0 格） | 3 | 0 | 0 | 73% |
| 第 3 关 | ~370 | 70%+ | 18（6.6 格） | 24 | 0 | 0 | 77% |
| 第 4 关 | ~445 | 70%+ | 22（6.6 格） | 22 | 0 | 1 | 81% |
| 第 5 关 | ~760 | 70%+ | 38（6.6 格） | 44 | 0 | 3 | 84% |
| 第 6 关 | ~1080 | 65%+ | 54（6.6 格） | 47 | 0 | 3 | 86% |

- **开局荒芜**：一棵树都没有，只有起点草地和 3 只以内的虫子。森林、动物都得自己养。
- **山只占一小片**：约 5% 的格子是石头山（山顶不能种，是羊驼的地方），其余坡地照常能种、能放动物、能浇水。
- **每局都不一样**：每个世界有自己的随机种子，海岸线、起伏、湖的位置都不同（见 `tests/shape.cjs` 的随机化检查）。

## 二、本轮按玩家反馈修的问题

1. **缩放时山峰和树木边缘闪烁**：原因是"同一个位置、同样占地、同样朝向"的方块在高度上互相重叠，两个面抢同一个平面（z-fighting）。
   现在岩裙、土柱、地面板、水面、山体、草丛的堆叠改成**首尾相接、互不重叠**，并加了自动检查：`tests/shape.cjs` 的「no two boxes fight over the same faces」会把每对同位置同尺寸的方块都算一遍，重叠就报错。
2. **第三、四关岛屿形状一模一样**：以前轮廓用的是写死的噪声种子，尺寸相近的关卡就长得像。
   现在每个世界自带随机种子（存档里记 `seed`），每局地形都不同。
3. **树太多、森林堵路**：开局不再生成任何树；手工"种森林"的印章也从"几乎实心的墙"改成**留缝隙的树丛**（密度 55%、半径 4.6 格），而且**小动物（虫、蝶、蜂、蛙、刺猬、鸡、兔）能穿过树丛**，只有大个子（羊、羊驼、野猪）会被挡住。
4. **高度略大的地方不能种/放动物/浇水**：以前"稍微高一点"就被判成石头山，整片岛不能玩。
   现在只有最高的那一小撮（约 5%）是石头山；**山脚（不超过 2.2 格）照常能种能放**，可玩格子占 73%–92%。
5. **创造/观察模式视角不一样**：切到观察模式时页脚被隐藏、舞台变高，但画布没有重新测量尺寸——显示尺寸 994×634、绘制缓冲却还停在 994×519，画面被纵向拉伸 22%，看起来就像"倾角变了"。
   第一次我用 `ResizeObserver` 修，**没生效**（在真实浏览器里截图核对才发现）；现在改成**每帧核对一次画布尺寸**，不一致就重新测量，并且切换模式时也会主动测量一次。
   真实浏览器实测：观察模式 `画布显示 994x634  绘制缓冲 994x634`（一致），两种模式下岛的宽高比分别为 1.487 与 1.491（差 0.3%，说明没有被拉伸）。

6. **不同高度放水／放石头，位置会"掉到平地"**：水和石头以前被强制按平地高度画，所以放在坡地上会往下沉。
   现在**水、石头、种子都跟着各自格子的高度**：高处的水面就停在**高处**，石头顶面 = 地面高度 + 石头自身高度。挖湖的印章会按**点击处的地面高度**挖出一片水平水面，不再把地形压平。
   顺带修掉一个隐藏问题：**种森林会把山坡压平**（印章会把经过的格子高度清零）。
   还多了一个效果：**相邻水面有落差时，落差处会画出水幕与飞溅**——之后要做"水往低处流"就已有基础。
   （老存档里的水都是 0 高度，读进来行为和以前完全一样。）

## 三、手工工具也变了

- **湖**：印章半径约 3.7 格，边界随噪声起伏，不是标准圆盘；"湖面"统计的是**全岛水面总和**（以前统计"最大的一片水"，所以再挖一个新湖数字常常不动）。
- **山**：一次造山最高 7 格（以前 2.8 格），越高越尖；最外圈是 1.6 格的低坡，能种能走。
- **森林**：一次约 20–36 棵树，留缝隙，不封路。

## 四、老存档会怎样（不会丢）

- 每个世界现在多记两样东西：`shape`（用哪一版海岸线规则）和 `seed`（这一局的随机种子）。
- 老存档没有这两个字段：按**第 1 版海岸线**（你熟悉的那个圆岛）+ 种子 0 校验，所以照旧能打开、能继续玩、能再保存，岛屿面积一点不变。
- 新开的世界用第 2 版海岸线 + 新种子；存档里声称新版却带着老海岸线会被明确拒绝（有测试守着）。
- 两条基线（老圆岛 / 新海岸线）的格子数与指纹都被 `tests/shape.cjs` 冻住了。

## 五、第五关的目标：我一度擅自改过，现已改回

我上一版把第五关的地形目标从「湖面 12 / 山地 5 / 森林 12」提到「65 / 65 / 120」，理由是"开局自带地形会让原目标自动打勾"。**但这是我自己的判断，不是你要求的**，而且它等于要求玩家造更多山、种更多林，方向也和"开局荒芜"相反。现已改回原值：

| 目标 | 现值（已改回） |
| --- | ---: |
| 湖面 | 12 |
| 山地 | 5 |
| 森林 | 12 |

副作用仍在：开局的湖与山会自动满足前两项，第三项因为"开局无树"必须靠玩家自己种。要不要调整由你决定（见文末"待你决定"）。

## 六、待你决定：山和林的量

你在第一条简报里要的是「山峰更高更险、湖泊更大、**森林更广袤**」；第二条反馈里要的是「**开局荒芜**、森林过度连通会堵路」。这两条方向相反，我上一版是自己选了后者并自作主张写进文档，这是我的错。现在的状态是：

- 山：约占陆地 5%，最高 6.6 格（只有它不能种，其余坡地都能种能放）
- 树：开局 0 棵；手工"森林"印章密度 55%、半径 4.6 格，一次约 20–36 棵

要我往哪边调都可以，你说一句就行。

## 六、怎么自己验证

```bash
npm test              # 39 项检查：22 行为 + 2 渲染 + 5 引导 + 10 形态/渲染护栏
npm run build         # 重新生成 dist/index.html（离线双击版）
npm run test:ecology  # 长时种群观察（会覆盖 docs/population-log.jsonl）
```

想亲眼看：`npm run dev` 后打开 <http://127.0.0.1:8877/>，**按 Ctrl+F5 强制刷新**，点「接过这座花园」进花园。
第 1 关就能看到起伏的坡地和不规则海岸；第 6 关能看到湖、几处石头山峰和大片等着你去种的空地。
每次「重玩」或新开一局，岛形都会不一样。

## 八、这次**没有**做的

- **岛屿形状的随机化（暂缓，按你的要求停手）**：现在种子只影响一个小噪声项，波瓣的相位是写死的，所以尺寸相近的关卡（第三、四关）看着仍然很像。彻底修需要让波瓣参数由种子决定，并且**把 `shape` 版本号从 2 升到 3**——否则最近这段时间存下的 shape 2 存档会被判成"海岸线不符"而打不开。我已经把改了一半的实现回退了，所以 `shape 2` 只有一份稳定定义。
- 动物模型精细化（还是方块叠方块）与配套动作
- 动物行为的涌现式重构与新玩法
- 专业撒点算法（泊松/蓝噪声）：目前用的是确定性的低频值噪声 + fBm
- `docs/population-log.jsonl` 与 `docs/验证记录.md` 的长时种群数字仍是旧版数据，需要重跑后更新
