## 2. 还剩下的活

### 2.1 移轴景深 + 颜色分级 ✅ 已经做完了

- 现状：**零依赖**，没有 `EffectComposer` / `BokehPass`（只有 `vendor/three.min.js`）；画布是透明的，UI 是"相纸"布局。
- 走的是上面那条 **a + c**：离屏 `WebGLRenderTarget` 渲染场景 → 全屏 quad 模糊 + 调色 → 回主画布。
  低画质档**完全不做后处理**（`postOn = q !== 'low'`）。没有上 CSS `filter: blur()` 那种糊法。
- 模糊按屏幕 y 算半径：`d = abs(vUv.y - uCenter)`，`k = smoothstep(uBand, uBand+0.30, d) * uStrength`，
  三环共 24 采样（12+8+4），**起始角度按像素 hash 抖动**——不抖的话固定网格会出现规则鬼影。
- 强度随缩放走（实测值）：zoom 1→0、0.7→0.036、0.5→0.338、0.35→0.603、0.2→0.748、0.14→0.75。
  所以**全岛总览一点不糊**，只有凑近看动物才有微缩感。

#### 这四条坑，下一个碰这里的人请直接抄

1. **离屏纹理必须留在 `LinearEncoding`，sRGB 编码自己在 shader 里做**。
   设成 `sRGBEncoding` 的话 three 采样时还会再解一次，白转两圈。
2. **模糊累加要用预乘 alpha**（`sum += vec4(s.rgb * s.a, s.a)`，最后 `vec4(sum.rgb/al, al)`）。
   画布是透明的，不这么做边缘必出黑边。
3. **`DOF_RADIUS` 别超过 9**。原本 14，在沙地那种规则图案上会拖出明显鬼影。
4. ⚠️ **顺手修了一个原有的 bug**：`setTimeOfDay()` 只改光照、不同步 `this.dayPhase`。
   任何读 `dayPhase` 的逻辑拿到的都是过时值（所以第一版颜色分级算出来白天夜晚**完全一样**，
   白测了两轮），而且从「夜晚」切回 `dynamic` 会从旧相位开始走。现在它同步 `dayPhase`。

#### 验收

## 3. 接触阴影：已经做完了，但踩过的坑值得记

**做法**（`src/render/scene.js`，构造函数 + `drawAnimals()`）：

业界叫 **contact shadow / blob shadow（接地阴影、接触阴影贴片）**——
脚底下贴一片**软边小贴片**，叠在地面上。它补的是阴影贴图原理上画不出来的那件事：
**接触点附近的环境光被物体自己挡住**（ambient occlusion），因为那不依赖太阳方向。
太阳斜时影子会跟物体脱开（peter-panning），贴片正好补上那一块。两者叠加，物体才像"踩在地上"。

几个关键决定：

1. **尺寸由模型自己算，不在 scene.js 里按物种写体型表。**
   `drawAnimals()` 里给模型的 `part()` 回调加了几行，顺便记录"贴着地那一层"的包围盒——
   那就是脚。改模型文件不会影响阴影。
2. **腾空越高越淡越小**：`exp(-lift/0.4)`，实测蜜蜂脚底 0.68 → 浓度掉到 10%，走兽（0.025~0.195）几乎满浓度。
3. **贴片宽度上限 0.8 格**，硬性的。
4. **贴片要比脚的包围盒宽 1.5 倍**——相机俯角 38° 时能挡住约 1.28 倍身高的地面，
   贴着脚的尺寸画会整个躲在肚子底下，实测只有 2~3 个像素宽。

### ⚠️ 之前踩过的三个坑

- **"把脚踩的那一整格地砖乘 0.78 压暗"被项目所有者否决了**，已整段回退（提交 `0aed620`）。
  一只羊的脚只占一格的一小块，整格染色读作"地砖换色"而不是"有影子"。
- **贴片不能放在 `state.y + 0.02`**：`state.y` 是双线性插值出来的平滑地面高度，
  在坡上会比旁边高的那格低一截，贴片会被地形埋掉——实测 10 片里有 2 片整个看不见。
  要用脚下那格的**真实台面**（`groundMax()`，中心加四偏移点取最高）。
- **别用"数像素"当唯一判据**：默认视角下每片只有 10 像素宽，开/关几乎看不出差别，
  量出来"只有 45 个像素变了"会误判成没生效。**先量投影跨度**，再决定要不要拉近看。

## 5. ⚠️ 之前那份文档里的错误结论（别再信）

**"透明的实例化贴片画不出来或者不可见"——这条是错的。**

实测：火苗的 `transparent + opacity 0.66 + depthWrite:false` 一直在正常显示；
云的渐隐（每实例 `aFade` 属性 + 片元里乘进 alpha）也验证过**真的接进了画面**
（`aFade` 从 1 → 0.5 → 0.25 单调下降，到 0 时有像素的格子正好为 0）。

当时失败的原因大概率是 `depthWrite`、`polygonOffset` 或材质池串色，**不是"透明贴片画不出来"**。
如果下一个人照着这句话绕路，那是白绕。

**"npm test 跑到访客/音频测试时卡住"** ——已修，见 §0。

**验证透明度属性是否真的接进画面时，读像素必须先把场景里其它网格全部藏起来**：
地形和悬崖是不透明的，会把 alpha 总量吃光，比值几乎不动，看上去像"属性没生效"。
按属性名手写黑名单最容易漏（本例漏了 `this.cliff`，2166 个方块）。直接 `scene.traverse` 全藏掉。

- ⚠️ **并行改动会让 `npm test` 的条数浮动**（66 → 65 都是正常的）。
  看到 FAIL 先确认是不是别的 agent 的中间态，别急着改自己的代码。
- ⚠️ `npm run build` 的体积会随音乐/录音素材变动（10 MB → 16 MB 都是正常的）。
- 文件是 **CRLF**；打补丁要先把 `\r\n` 归一化成 `\n` 再写回。
- PowerShell 里不要用 `node -e` 写带引号/正则的脚本（会被拆坏）——**写成 `.cjs` 文件再跑**。
- 写文件工具可能吞字符：提交信息一律写进文件用 `git commit -F`，提交后 `git log -1 --format=%B` 复核。
- github.com 直连不通，走代理：`git -c http.proxy=http://127.0.0.1:7890 -c https.proxy=http://127.0.0.1:7890 <命令>`
