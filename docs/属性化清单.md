# 属性化清单：把脚本式行为改成「属性 × 环境」

这份文档只做一件事：把工程里**还写着"某某动物会怎样"的地方**逐条列出来，说明该给它什么属性、
加什么规则、怎么验收。**本轮不实施**，等你和队友定方向。

判断一条改完了的标准（三条都满足才算）：

1. **代码里不再出现** `a.type==='某某'` / `['羊','牛'].includes(a.type)` 这类按物种写的分支；
2. **属性表里能读出原因**——看 `TRAITS[type]` 就知道它为什么这样行动；
3. **有等价性测试**：改造前后行为逐格/逐拍一致（重构不该改玩法）。

## 一、三类东西都可以有属性

你举的例子（羊驼口水 → 羊吃草 → 醉）之所以好，是因为它同时用到了三类属性：

| 类别 | 已有属性 | 可以再加 |
| --- | --- | --- |
| **动物** | `move` `mass` `climb` `diet` `plants` `eats` | `appetite` `metabolism` `restlessness` `likes` `bulk` `footing` `crave` `spit` `sows` `fear` `trample` |
| **植物（格子）** | `plant` `age` `plantLife` `fert` `moist` | `sugar` 含糖 `ferment` 发酵度 `film` 口水膜 `wood` 木质 `trampled` 踩踏度 |
| **环境（格子）** | `ground` `elevation` `moist` `fert` `flow` `fire` `ash` | `heat` 热 `shade` 阴影 `wind` 风 `scent` 气味 `nest` 巢 |

规则写在**属性之间**，不写在物种之间。上面这 20 来个属性任意组合，玩法空间就已经比 15 个物种大得多。

## 二、样板：把「喝醉的羊」改成属性

**现状**（`src/sim/core.js` 的进食段）：

```js
const fermented = d.plant === 'bush' && d.age >= 150;          // 只有浆果丛、只有"成熟"这一个条件
if (fermented && a.type === 'sheep') { a.drunk = 60; ... }      // 只有羊会醉
```

**问题**：只有一种植物、一个物种、一种醉法；换任何条件都要再写一条 `if`。

**属性化设计**（全部是数值，没有任何"羊会醉"的字样）：

- 植物/格子属性
  - `sugar`：由**植物种类 + 年龄**推出（成熟浆果 0.9、花 0.4、草 0.1、种子 0.2），不再单独判 `plant==='bush'&&age>=150`
  - `ferment`：每拍增长 `+= sugar × 0.003 × (暴晒?1.6:1)`，所以"放过一阵子的甜东西"才会发酵
  - `film` / `filmSugar`：表面有没有口水膜、膜里带多少糖
- 动物属性
  - `metabolism`：代谢率（鸟 0.3、兔 0.8、羊 1.0、野猪 1.4、羊驼 1.1）——代谢越高越难醉
  - `crave`：想找的食物特征（羊驼 `{sugar: >0.6}`，羊 `{grass:true}`，野猪 `{any:true}`）
  - `spit`：吃完会不会吐（羊驼 0.8、羊 0）
- 通用规则（三条，对所有物种一视同仁）
  1. 进食时 `alcohol += sugar × (1 + ferment × 8) / metabolism`；`alcohol > 1` 就 `drunk`
  2. 进食后若 `spit > 0`：把 `film=1, filmSugar=sugar` 抹到**附近随机一格**的植物上
  3. 吃到 `film=1` 的植物时，额外获得 `filmSugar` 的糖分（一样会醉）
  4. `alcohol` 每拍衰减 `-0.02`，所以醉了会醒

**结果**：`羊驼爱吃甜 → 上山找浆果 → 吃完整的 → 到处吐口水 → 口水沾到草 → 羊吃了那丛草 → 醉`
这条链会**自己出现**。想调整只改数值：把羊驼的 `spit` 调到 0.1，"口水醉羊"就变成稀有事件。

**验收**：
- 等价性：老的"成熟浆果丛喂羊会醉"仍然发生（用改造前的谓词写测试逐格比对）
- 新行为：羊驼在浆果丛旁吐口水后，羊吃到那格会醉；野猪因为 `metabolism` 高，要吃更多才醉
- 长时生态不崩

## 四、清单 B：新玩法（属性 × 环境，来自你给的例子）

| # | 玩法 | 需要的属性 | 规则（一句话） | 可见效果 |
| --- | --- | --- | --- | --- |
| B1 | **醉酒链**（样板） | 植物 `sugar/ferment/film`；动物 `metabolism/crave/spit/alcohol` | 见第二节 | 羊驼吐口水，羊吃了会醉、会晃 |
| B2 | 热与阴影 | 格子 `heat/shade`；动物 `heatTolerance` | 热 > 耐受就往阴影/水里移动，过热掉血 | 正午羊群挤到树下 |
| B3 | 风 | 格子 `wind`；动物 `mass` | `wind / mass` 超过阈值就被推走；蝴蝶传粉距离变长 | 大风天蝴蝶被吹散 |
| B4 | 踩踏与土壤 | 格子 `trampled`；动物 `mass/trample` | 走过 `trampled += mass/8`；高于阈值草变裸土、渗水变差 | 畜群把草地踩成小路 |
| B5 | 木材与倒树 | 植物 `wood`；动物 `mass`、火/风强度 | 撞击强度 > `wood` 时树倒，倒下的树变成障碍 | 野猪拱倒小树、火后倒木挡路 |

| B7 | 气味追踪 | 格子 `scent`；动物 `smell/fear` | 猎物留下气味，捕食者沿气味追踪；`fear` 高的先跑 | 狐狸真的"追"兔子 |
| B8 | 恐惧与逃跑 | 动物 `fear/speed` | 附近有 `eats` 自己的动物时优先逃跑，方向由 `climb/move` 决定 | 羊群炸开往坡上跑 |

其中 **B1 是唯一"三类属性都用上"的样板**，建议先做它：做通了，B2–B8 只是换属性名。

## 六、每条改动的验收配方（照这个顺序做）

1. **先写等价性测试**：把改造前的写死谓词抄进测试，逐格比对改造后的结果必须完全一致。
   （上次 `eatPlants` 重构就是这么干的：700+ 样本 × 15 物种，还当场抓到 `grass` 漏了年龄门槛。）
2. **再写行为测试**：新属性/新规则能触发，并且能被观察到（不能只测内部字段）。
3. `npm test` 全绿（现在是 50 项）。
4. **长时生态观察**：`node tests/ecology.cjs`，3 个种子 × 3000 秒，数量级不能崩（现在是 180/166/202）。
5. **存档**：新字段 → 加进 `save.js` 白名单 + 范围校验 + 老存档默认值 + 越界必须抛错。
6. **若新增方块/模型** → 跑 `tests/shape.cjs` 的共面重叠扫描（闪烁就是这么抓出来的）。
7. **若新增随机消耗** → 测试固定种子，并预期旧测试可能要跟着调（见第八节）。

## 八、必须守的规矩（都是已经踩过的坑）

- **单一随机流**：`rand(s)` 只有一条流。任何新增的随机消耗都会**平移后面所有事件**——我们已经被这个绊了两次
  （加 `ensureFlow`、加爬坡规则之后，旧的行为测试都需要重定标）。改完必须重跑长时生态。
- **存档是严格校验的**：新字段漏加白名单 = 存档往返丢数据；范围写错 = 玩家存档打不开。两者都有测试会抓。
- **共面重叠**：新增方块一定要跑 `tests/shape.cjs`，否则缩放时又会出现边缘闪烁。
- **属性要有范围测试**：像 `tests/traits.cjs` 那样逐属性断言合法区间，否则写错一个数值不会被发现。
- **属性命名统一**：全小写、单数、英文；并在本文档维护一张总表（加一条就补一行）。

## 九、做完全部之后会长出什么（验收的"体感"标准）

不看清单、只看现象——如果下面这些能**自己发生**，就算真的到涌现式了：

1. 你挖了一条渠，羊群顺着嫩草聚过来，把堤岸踩秃，某次开挖让水改道，冲走了几只羊；
2. 羊驼在山上吃浆果、吐口水，羊吃了口水草开始晃，野猪因为代谢高没醉；
3. 一场火之后倒木挡路，鹿绕道，狐狸沿着气味追兔子，兔子钻进树林（`bulk` 小）逃掉；
4. 你什么都没做，只是看了五分钟，日志里出现的句子是你**没写过**的组合。
